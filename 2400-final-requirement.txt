Detailed Project Specification & Requirements
1. Core Project Features (Detailed Scope of Work)
A) Hadith Library
Task: Design and develop the database architecture and User Interface (UI) to display Hadith categories, chapters/sections, and the main Hadith text.

Access Control: As per the client's final requirements, the Hadith Library will be a Premium Feature locked under the subscription model. Users must have an active subscription to unlock and view this section.

B) Knowledge Library (Pure Text)
Content Volume: The library will launch with a maximum of 50 initial articles (to be completed by the Sheikh within 2 months). Post-launch, the architecture must support uploading 1 new article weekly until the library reaches its target of 300+ articles.

Multilingual Architecture: The database must be structured to support an unlimited number of languages. Content will initially be uploaded in German, but the backend must allow adding 12–13+ additional languages in the future without requiring any changes to the source code.

100% Offline Support (Offline Reading): This is a mandatory requirement. When online, articles will automatically cache or sync to the phone’s Local Storage (SQLite/Room/Hive/Realm). This ensures users can access, view, and read all downloaded articles anytime without an internet connection.

2. Payment & Subscription System (Payment Breakdown)
A) Monthly / Yearly Subscription Tiers
Subscription Models: The app will feature two main subscription durations: Monthly and Yearly.

Access Control: Upon a successful transaction, the user's status will update to isPremium: true, which will simultaneously remove the lock from both the Hadith Library and the Knowledge Library.

Expiration Logic: Once the subscription period expires, access to these libraries will automatically lock until renewed.

B) One-time Donation (One-time Contribution)
Custom Amounts: A dedicated "Support Us" or "Donate" button will be available on the profile or subscription screen.

Feature: Users can contribute custom one-time amounts (e.g., 5€, 10€, 20€, 50€, etc.) to financially support the app and the client's family. This feature operates independently of the premium subscription.

Gateway & Currency: The primary currency for transactions will be Euro (€). The payment gateway must support European payment methods, specifically Credit/Debit cards and SEPA Direct Debit (highly preferred in Germany).

3. User Interface & Design (Detailed UI/UX)
A) Black & White Theme
Target Sections: Quran, Hadith, Tafsir, Duas, and Knowledge Library.

Design Guidelines: These reading sections must completely exclude vibrant accents, colored buttons, or green/blue tints. The UI must utilize a minimalist black-and-white, typography-focused aesthetic to replicate the feel of reading a premium physical Islamic book.

B) Theme Toggle & Background Control (Theme Selector)
Users will have access to an "Aa" (Theme) button inside the reading screens to dynamically select their preferred background contrast:

Light Mode: Pure white background with deep black text.

Dark Mode: Pure black background with white/off-white text.

Sepia / Soft Mode: A soft, low-contrast gray or off-white background option designed specifically to prevent eye strain during long reading sessions or night-time use.

C) Subscription Screen Notice (Subscription Warning)
An honest, explicit text notice must be placed directly above or below the subscription checkout buttons to keep users properly informed:

"Notice: The Knowledge Library is live but currently under construction! We currently have a maximum of 50 initial articles available. New articles will be added weekly (1 article per week) until the library reaches its full collection of 300+ articles. Thank you for supporting our project!"

4. Admin Panel & Security (Admin & Writer Interface)
Copy-Paste Friendly Rich Text Editor (Draft/Quill Editor): Since the client and the Sheikh will be copying text directly from Microsoft Word (.docx) files, the admin panel must feature a Rich Text Editor. This will automatically preserve essential text formatting such as bold text, italics, paragraph breaks, and bulleted lists upon pasting.

Language Selector Dropdown: When publishing an article, the admin will use a dropdown menu (e.g., German, English, Arabic) to easily tag and assign the article's language.

Read-Only App Security: Data pushed from the Admin Panel will be securely locked inside the cloud database. The mobile application front-end will render this text in a strict "Read-Only" container. Regular app users will have zero technical capability to edit, modify, or tamper with the database text.
